## What to find out, per call

1. **Scout vision (5.4).** Does an image as `image_url` with a data address work, or does the model want another form? What does JSON mode return with an image (text, or an object)? The largest photo it takes (the server sends what the upload route kept, up to 10 MB). Latency. Cost in neurons.
   *If no:* change the message shape in `scout.ts`; the reader already takes text or an object.
2. **FLUX.2 klein (5.3).** Does the multipart call work from the binding? The page says reference images must be smaller than 512 by 512; the shell sends 512 on the longest side, so does exactly 512 fail? What comes back (base64 in `image`, or something else; JPEG or PNG)? Is a sketch plus caption good enough for World Labs to build from? Zero data retention (the page lists it) before any sketch is sent. Cost per call.
   *If no:* resize the sketch to 511, or set `IMAGE_MODEL_ID=@cf/black-forest-labs/flux-2-dev`.
3. **Scout text.** The answer's shape; whether the 6 s default deadline is enough; tokens and cost per ghost turn.
   *If no:* `readChatText` takes one more shape; raise the deadline.
4. **Llama Guard 3.** The answer's real shape; which codes it gives for harmless short text (nicknames such as "Mr. Whiskers", place names, one-word Zone names); languages it does not list (it lists English, French, German, Hindi, Italian, Portuguese, Spanish and Thai); the roles it accepts. About 500 ms per call, a documented figure.
   *If it over-blocks:* the codes are kept in the answer; a caller can waive a code. Today every code blocks.
5. **Background removal.** The documentation covers `segment=foreground` for the URL form and `cf.image` only (BiRefNet through Workers AI, billed as an ordinary unique transformation, no neurons). Does the binding's `transform` take it? The default `wrangler dev` runs an offline binding with only width, height, rotate and format, so this needs `wrangler dev --remote` or a deployed Worker, and an Images Paid subscription. Clean edges, hair, a pale background, and the PNG size at 768 tall (the Ghost Profile takes at most 1 MB).
   *If no:* a `fetch` with `cf.image: { segment: "foreground" }` from a URL the service can reach (a signed, short-lived address of the portrait in R2).

## How to run it without a leak

- Declare the bindings yourself in `api/wrangler.jsonc` (`"ai": { "binding": "AI" }`, `"images": { "binding": "IMAGES" }`) and run `wrangler dev --remote` (or deploy a scratch Worker). In dev the `AI` binding always reaches your account.
- Use three photos and three sketches you do not mind sending, a few ghost prompts, ten short texts for the guard and three portraits. Each call is a few neurons or one image transformation; the total should be well under a dollar.
- Do the calls through the guarded doors, so the meter caps apply (`IMAGE_SESSION_CAP`, `LLM_SESSION_CAP`, and the day caps). Do not call a model from a script outside `api/src/guarded/`: the `guarded-only` test fails any file that does.
- Record here: the real answer for each call, latency, neurons per call, and the decision for each *If no* above. Save scrubbed answers as fixtures in `shared/fixtures/ai/`, then update the unverified list in `.kiro/steering/tech.md` (items 2, 10, 11 and 12).
