# Spike 1.1: World Labs World API, one photo to one world

Written 2026-11-15. Spec: `.kiro/specs/world-pipeline` task 1.1.

**Status in one line: not run.** Nothing was sent to the service and no credit was spent. This file records what the published documentation says, which of our assumptions it changes, and exactly what only a real run can answer. The run needs a World API key and prepaid credits, which only the owner can supply.

## Why it was not run

- The only World Labs key on this machine belongs to the **Atlas** CLI (`worldlabs auth status` answers `api.atlas.worldlabs.ai`). Atlas is a different product from the **World API** (Marble) this project is built on: its tasks are `atlasGenerate`, `images2PosedRGBD`, `posedImages2Splats` and so on, with its own projects, keys and billing. That key was not read and not used.
- The World API uses `https://api.worldlabs.ai`, the header `WLT-Api-Key`, and credits bought at https://platform.worldlabs.ai. Credits bought for the Marble web app **cannot** be used with the API.
- Spending money is the owner's decision (`.kiro/steering/security-and-cost.md`).

## What was done without spending

1. Read the public World API documentation and its OpenAPI file (https://docs.worldlabs.ai/llms.txt and https://docs.worldlabs.ai/api/reference/openapi.yaml).
2. Wrote the runner for the real run: `tools/worldlabs-spike/spike.mjs` (library `tools/lib/worldlabs-spike.mjs`, tests `tools/test/worldlabs-spike.test.mjs`, 18 passing against a local fake of the API). It is not the dev MCP of task 0 (still only a README); it does the same recording with less to build.
3. Ran the real Worker adapter on `wrangler dev` against a local stand-in of the API (`api/dev/fake-world-api.mjs`, the documentation's shapes, nothing paid): the job, adapter and ingest work end to end on the real runtime. That checks our code, not the service: it proves nothing about what the service really answers.

## What the documentation says

Everything in this table is **documented, not yet confirmed by a run**.

| Question | Documented answer | Differs from what we assumed? |
|---|---|---|
| Base and key | `https://api.worldlabs.ai`, header `WLT-Api-Key` | no |
| Start | `POST /marble/v1/worlds:generate` answers `{operation_id, done, created_at, updated_at, expires_at, metadata, error, response, cost}`; errors `402` (credits), `422` (bad body), `400` (bad input or content policy), `429` (rate limit) | the path has `/marble/v1/` in front |
| Poll | `GET /marble/v1/operations/{operation_id}`, the same shape; when `done` is true and `error` is empty, `response` **is the finished World**, so a second call is not needed; `metadata.world_id` and `metadata.progress {status, description}` | the world comes back inside the operation |
| Image request | `world_prompt: {type: "image", image_prompt: {source: "data_base64", data_base64, extension}, is_pano: "auto" (default), text_prompt?, disable_recaption?}`; also `source: "uri"` (must be publicly fetchable) and `source: "media_asset"` (upload first); recommended formats jpg, jpeg, png, webp | field names now known; the image size limit for an image is **not documented** (a video may be 100 MB) |
| Other request fields | `display_name` (at most 64 characters), `model` (`marble-1.0-draft`, `marble-1.0`, `marble-1.1` the default, `marble-1.1-plus`), `permission`, `tags` (at most 10), `seed` | `model` is `marble-1.1`, as we had |
| Privacy default | `permission` defaults to `{public: false, allow_id_access: false, allowed_readers: [], allowed_writers: []}`: private | the runner sends it explicitly |
| World fields | `world_id` in the schema (the examples show `id`: the documentation disagrees with itself, so read `world_id`, then `id`, then `metadata.world_id`), `display_name`, `world_marble_url`, `model`, `assets`, `world_prompt` | new |
| Splats | `assets.splats.spz_urls` with keys `500k`, `100k` and `full_res`; a `.ply` is a separate export call | key names now known |
| Scale and ground | `assets.splats.semantics_metadata.metric_scale_factor` (multiply every position and isotropic scale by it; `1.0` means it could not be inferred) and `ground_plane_offset` (after scaling, subtract it from Y to put the ground at y = 0, in the file's own frame). Both are present on every world made after December 2025 | **new, and it replaces our placeholder pose** (see below) |
| Frame | the page https://docs.worldlabs.ai/api/rendering-spz.md says the SPZ files are in the `marble_raw_opencv` frame (x right, y down, z forward) and that the service's own viewer turns them 180 degrees about x; the OpenAPI text for `semantics_metadata` says the same about scale and ground | **new**: the up axis is no longer open as a question, but no example world shows it |
| Collider | `assets.mesh.collider_mesh_url`, GLB, present on a finished world | name known |
| Meshes | `hq_mesh_url` and `full_res_mesh_url` appear only after an export call; the HQ export costs 3,500 credits | never call it |
| Panorama, thumbnail, caption | `assets.imagery.pano_url`, `assets.thumbnail_url`, `assets.caption` (AI description) | names known; their formats are not documented |
| Time | about 5 minutes | as we had |
| Cost | $1.00 = 1,250 credits (minimum purchase 6,250 credits, $5). One ordinary photo: a pano step of 80, then 1,500 for `marble-1.0`/`marble-1.1` = **1,580 credits, about $1.26**; the draft model is 80 + 150 = **230 credits, about $0.18**; `marble-1.1-plus` is 1,500 plus up to 1,500 more for a big world. The settled cost comes back as `cost {total_credits, line_items}` | the draft model is a cheap way to see every field name |
| Free calls | `GET /marble/v1/credits` (`{remaining_credits}`), polling, and media-asset upload and management cost nothing | new: the balance can be read before any spend |
| Rate limit | by default about 3 world starts a minute and 60 an hour per API user; `429` with `Retry-After` | far above our own caps |
| Overage | the balance check is a low-balance threshold, not a per-request estimate: a request admitted at a low balance can take the balance **below zero**, and the overage is billed at the end of the month. Turning auto-refill off does not stop it | **new and important** (see below) |
| Delete | `DELETE /marble/v1/worlds/{world_id}` exists | new |
| Expiry | the operation record has `expires_at` (one hour after creation in the example). Whether the asset addresses expire, and when, is **not documented** | still open |

## What this changes in our plan

1. **The pose is no longer a guess.** `poseFromService` (`shared/src/world/ingest.ts`, property-tested) builds it from the documentation: `orientation.upFix` is the half turn about x, `[1, 0, 0, 0]`; `orientation.scale` is `metric_scale_factor`; the ground is at y = `ground_plane_offset` before the turn, so `floorY` is `-ground_plane_offset` after it; the spawn is at the origin (where the picture was taken from) 1.6 m above the floor, and the file's forward (z) becomes the viewer's -z, so it looks the way the picture looks. A scale outside 0.01 to 100 reads as 1 and a ground height beyond 100 m as 0. This is a reading of the documentation: one real world in the viewer must confirm upright, facing and floor.
2. **The real adapter is written** (`HttpWorldLabs`, `api/src/guarded/worldlabs-http.ts`): the start and poll calls, the reading of the finished world into `SourceWorld`, and the file download, from the documented shapes. Its tests use the documentation's examples (`shared/fixtures/worldlabs/docs-examples.json`: the quickstart's operation and world answers with invented addresses, the OpenAPI 402 body, and an error and a cost built from the schema), not a recording. After a run, replace that file's entries with the recorded ones and re-run the tests; any difference is a finding.
3. **Privacy.** A photo sent to the service is stored by them, for a time the documentation does not state. Our principle is "personal photos are private, short retention". Recommended, for the owner to decide: send the photo inline (`data_base64`, so nothing is left in a media-asset store), keep the default private permission, and call `DELETE /worlds/{world_id}` once ingest has copied the files, so the upstream copy goes too. That adds one call to 7.3 and is part of what "Delete my place" (Requirement 10.2) should mean.
4. **The spend cap is not a hard stop on their side.** Because overage is allowed, the project's own `SpendGuard` caps are the only hard limit, and the platform balance should be kept small (the $5 minimum) so the exposure is bounded. Auto-refill should stay off, though that alone does not cap anything.
5. **Use the draft model first.** One draft world (about $0.18) shows every field name, every format, the timing and the cost lines. One standard world (about $1.26) is then only needed to judge quality.

## How to run it

1. Create a **World API** key at https://platform.worldlabs.ai and buy the minimum credits there (not in the Marble app). Put the key in your own shell: `export WLT_API_KEY=...` (never in chat or a file in the repo).
2. A look, no spend (reads the balance, prints the plan):
   `node tools/worldlabs-spike/spike.mjs --image path/to/photo.jpg`
3. The draft run, about 230 credits ($0.18):
   `node tools/worldlabs-spike/spike.mjs --image path/to/photo.jpg --yes-spend --delete-after --download scratch/wl`
4. Later, one standard run, about 1,580 credits ($1.26):
   `node tools/worldlabs-spike/spike.mjs --image path/to/photo.jpg --model marble-1.1 --max-credits 1600 --yes-spend`

The runner refuses to send anything that costs without `--yes-spend`, refuses a run that could pass `--max-credits` (default 300) or the total cap `WL_MAX_SPEND_CREDITS` (default 6000, kept in `tools/worldlabs-mcp/.ledger.json`, git-ignored), refuses when the balance is below the most the run could cost, sends the key only to `api.worldlabs.ai`, never prints the key, an address or the picture, and saves the response with every address and id replaced (`shared/fixtures/worldlabs/<model>-<time>.json` and `...-summary.json`).
