# Spike 1.1 run plan: one real world (for the owner's approval)

Written 2026-11-16. Spec: `.kiro/specs/world-pipeline` task 1.1. Background and every
documented-but-unconfirmed fact: `docs/spikes/1.1.md`. **Nothing here has been run, and
nothing will be run until the owner approves this plan and names the cap.**

## What one run buys

One world from one photo on the World Labs World API (Marble), through the tested runner
`tools/worldlabs-spike/spike.mjs` (18 tests against a local fake, green 2026-11-16). It
confirms or corrects, with a recording, everything the adapter and ingest now believe from
the documentation alone:

- the real operation and world answers, field for field (against
  `shared/fixtures/worldlabs/docs-examples.json`, which the adapter tests use today);
- the asset names and formats: SPZ LODs (`100k`, `500k`, `full_res`), the collider GLB,
  the panorama and thumbnail formats, `Range` support, whether addresses are signed or expire;
- the settled cost line by line, the wall-clock time, `world_id` or `id`;
- `semantics_metadata` on a real world (`metric_scale_factor`, `ground_plane_offset`),
  which `poseFromService` turns into the manifest orientation, scale, floor and spawn;
- whether `DELETE` removes the upstream files at once (the privacy plan in `1.1.md`);
- with `--download`, the real files themselves: the first fixture a viewer can open.
  World-viewer task 1 (the Spark spike, `docs/spikes/2.1.md`) and ghost-engine 6.3 both
  wait on exactly this.

## Cost, stated before anything is sent

- A **standard** world (`marble-1.1`, the model the game would use): 80 (pano step) +
  1,500 = **1,580 credits ≈ $1.26**. `docs/spikes/1.1.md` recommends a **draft** world
  first (`marble-1.0-draft`: 230 credits ≈ $0.18) because it shows every field name for
  a seventh of the price; the standard run after it only judges quality. Both together
  are about **$1.44**. The owner chooses: draft only, standard only, or draft then standard.
- Credits are prepaid at https://platform.worldlabs.ai; the minimum purchase is 6,250
  credits ($5). Marble web-app credits do not work with the API.
- The service allows a balance to go below zero and bills the overage at month end
  (documented). The runner is the hard stop: it refuses when the balance is below the
  run's ceiling, refuses past `--max-credits`, and keeps a running ledger against
  `WL_MAX_SPEND_CREDITS` (default 6,000 ≈ $4.80 across all runs, ever). Recommended for
  this run: `--max-credits 300` (draft) or `1600` (standard), and leave the total cap at
  6,000. Keep the platform balance at the $5 minimum and auto-refill off.
- Polling, the balance check and the downloads are free. A refused start (4xx) is not
  charged in the runner's ledger; whether a timed-out or 5xx start is charged is one of
  the questions the run answers (the balance is read before and after).

## Before the run (owner, once)

1. Create a **World API** key at https://platform.worldlabs.ai and buy the minimum
   credits there. The Atlas CLI key on this machine is a different product and will not
   be used (the runner rejects a key the credit check cannot read).
2. Put the key in the shell that runs the spike: `export WLT_API_KEY=...`. Never in
   chat, never in a repo file. (Checked 2026-11-16: not set in this session's shell,
   and no ledger exists yet, so nothing has ever been spent through the runner.)
3. Pick the photo. Recommendation: a place with **no people and nothing private** (the
   photo is stored upstream for an unstated time; `--delete-after` below tests the
   removal), a clear floor and walls so upright/facing/floor can be judged, jpg/png/webp,
   under 10 MB. A photo already used for a Gallery mock is ideal.

## The run (in this order, stopping on any surprise)

1. **A look, no spend.** Reads the balance, prints the plan and the exact request, sends
   nothing that costs:
   `node tools/worldlabs-spike/spike.mjs --image <photo>`
   Check the printed balance, model and estimate against the cap you approved.
2. **The draft world** (if chosen), with the upstream copy deleted afterwards and the
   files downloaded to the git-ignored `scratch/`:
   `node tools/worldlabs-spike/spike.mjs --image <photo> --yes-spend --delete-after --download scratch/wl-draft`
   About 5 minutes of polling. It writes the ledger first, so an interrupted run still counts.
3. **Read the recording before any second spend**: `shared/fixtures/worldlabs/<model>-<time>.json`
   and `...-summary.json` (scrubbed: every address and id replaced, safe to commit), and
   the balance-before/after inside the summary. If a field name, format or cost line
   differs from `docs/spikes/1.1.md`, that is a finding to record, not a reason to re-run.
4. **The standard world** (if chosen), same photo, so quality is the only difference:
   `node tools/worldlabs-spike/spike.mjs --image <photo> --model marble-1.1 --max-credits 1600 --yes-spend --delete-after --download scratch/wl-1.1`

## After the run (agent, no further spend)

1. Fill the Results table in `docs/spikes/1.1.md`, commit the two scrubbed fixtures,
   update `.kiro/steering/worldlabs-api.md` and the unverified list in
   `.kiro/steering/tech.md` from "documented" to what the recording shows.
2. Point the adapter tests (`api/src/guarded/worldlabs-http.ts`) at the recorded fixture
   in place of the documentation examples; any failure is a real difference to fix.
   Re-run the api and shared suites.
3. Tick world-pipeline 1.1. The downloaded SPZ, collider and pano in `scratch/` become
   the input to world-viewer task 1 (Spark spike) — which still needs its own short
   plan, because it chooses the Spark version.

## What could go wrong, and the answer ready for each

- **The service charges more than the estimate.** The settled `cost.line_items` in the
  recording shows it; the ledger is corrected to the real number; no second run happens
  until the owner sees it.
- **The world comes back upside down or the floor is wrong.** Expected possibility:
  `poseFromService` is a reading of the documentation. The downloaded SPZ in the viewer
  spike settles it; the fix is in one pure function with property tests.
- **Asset addresses need the key, or expire within the hour.** The runner's `HEAD`
  checks and downloads happen in the same run, and the summary records the statuses;
  ingest (7.3) then downloads immediately, which is already its design.
- **The photo is refused (400/422).** No charge is recorded by the runner for a refused
  start; the error text (redacted) says why. A different photo is a new approval, not a retry.
